# Crew reporting API

Use a normal authenticated Supabase client. Never send a service-role key to a browser. Generated schema types are in `src/database.types.ts`.

## Submit

```ts
// Keep this UUID unchanged if this exact request needs to be retried.
const requestId = crypto.randomUUID();
const { data, error } = await supabase.rpc("submit_hazard_report", {
  p_request_id: requestId,
  p_site_id: siteId,
  p_type: "debris", // debris | wildlife | downed_line | washout | other
  p_severity: 2, // 1–3
  p_lat: 29.652,
  p_lon: -82.325,
  // p_photo_id: reservedPhoto.id, // optional; must be uploaded first
});
```

Response: `{ outcome: 'created' | 'merged', report: { id, site_id, reporter_id, type, severity, status, confirmations, latitude, longitude, created_at, last_confirmed_at, resolved_at, resolution_reason, is_active } }`.

Retries return the original response snapshot. Fetch the report again when current state matters. A request ID reused with changed inputs fails. Changing a form after an ambiguous failure represents a new submission; check the feed if unsure whether the previous submission committed.

## Photo upload

```ts
// Preserve photoId too if the reservation response is lost.
const photoId = crypto.randomUUID();
const { data: photo, error: reservationError } = await supabase.rpc(
  "reserve_hazard_photo",
  {
    p_photo_id: photoId,
    p_site_id: siteId,
    p_content_type: file.type,
  },
);
if (reservationError) throw reservationError;
const { error: uploadError } = await supabase.storage
  .from("hazard-photos")
  .upload(photo.object_path, file, { contentType: file.type, upsert: false });
if (uploadError) throw uploadError;
// Now submit with p_photo_id: photo.id. Reservations expire after one hour.
```

Supported MIME types: `image/jpeg`, `image/png`, `image/webp`. Maximum 5 MiB. The object path is generated by the server. Authenticated team members can generate five-minute display URLs with `createSignedUrl(path, 300)` for attached photos. Store paths in data, not signed URLs. Discard an unattached upload through `storage.remove([path])`; attached photos cannot be changed or deleted by clients.

## Check in

```ts
await supabase.rpc("checkin_hazard_report", {
  p_request_id: crypto.randomUUID(), // retain for retries
  p_report_id: reportId,
  p_still_there: true, // false resolves the report
});
```

Returns `{ outcome: 'confirmed' | 'resolved', report: ... }`. Neither a resolved nor an expired report can reopen. Submit a new hazard instead. Any accepted submission/check-in completes the current reminder tasks for that hazard.

## Read feeds

```ts
const reports = await supabase
  .from("crew_hazard_feed")
  .select("*")
  .eq("site_id", siteId)
  .eq("is_active", true)
  .order("last_confirmed_at", { ascending: false });

const history = await supabase
  .from("crew_observation_feed")
  .select("*")
  .eq("site_id", siteId)
  .order("created_at", { ascending: false });

const metrics = await supabase.rpc("get_site_crew_metrics", {
  p_site_id: siteId,
});
// [{ crew_risk_term: 0..2, wildlife_subscore: 0..10, open_report_count }]

const reminders = await supabase
  .from("hazard_checkin_tasks")
  .select("*")
  .is("completed_at", null); // RLS automatically scopes recipients
```

History contains observation coordinates, site, type, action, actor, severity and time. Events are durable, and the alert/briefing worker can query `hazard_events` with `.gt('id', lastProcessedId).order('id').limit(100)`. Each consumer must persist its own cursor and deduplicate outbound delivery by event ID. Events describe changes; resolve each report's current state when composing a briefing.

## Live updates

Subscribe to `hazard_reports` filtered by site ID, and to the current user's `hazard_checkin_tasks`. Both are in the local Realtime publication and protected by RLS. Events should trigger a refresh of the feed and metrics; they are not a replacement for querying current state.

Wait for the channel's `system` event with `extension: 'postgres_changes', status: 'ok'` before declaring the feed live. `SUBSCRIBED` alone means the channel connected. Refresh once when changes become ready to cover the initial-query/subscription gap. See the [Supabase troubleshooting guide](https://supabase.com/docs/guides/troubleshooting/realtime-postgres-changes-troubleshooting). The UI also refreshes every minute so time decay and expiration remain visible.

## Errors and workers

- SQLSTATE `42501`: site membership / authorization failure.
- SQLSTATE `22023`: invalid input, conflicting request ID, unusable photo, or invalid hazard state.
- Expiry/reminder generation: `run_hazard_maintenance()`, restricted to trusted workers and pg_cron.
- Orphan metadata pruning: `prune_hazard_photo_reservations(ids)`, restricted to workers; delete bytes via Storage first.
- RPCs return errors through Supabase's normal `{ data, error }` response. Inspect `error` before using data.

The database never accepts caller-supplied reporter IDs, confirmation totals, timestamps or resolution state. Idempotency records persist for the lifetime of this demo database; hosted retention must be defined along with a guaranteed client retry window.
