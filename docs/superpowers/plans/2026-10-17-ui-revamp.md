# ControlWard UI Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "Field Ledger" UI with a Notion-like app: a judge-facing landing page, a sidebar shell with one page at a time, a supervisor Sites page (ranked table + live map), a map-first crew page with a slide-in report drawer, and purposeful motion.

**Architecture:** Frontend-only. Hash routing (`#/sites`, `#/alerts`, …) keeps the mock's query flags (`?safety=stale`) working. Existing feature components (alerts, briefing, safety, crew, push, feed, map) keep their logic and are re-skinned and re-homed onto pages; new pieces are the shell, landing, sites table, report drawer, stop-work banner and one cross-site data query. The map component stops remounting per site so it can fly between sites.

**Tech Stack:** React 19, TypeScript, Vite, CSS Modules, MapLibre GL 6, Supabase JS, Playwright (`tests/ui-design` against the in-browser mock), `node --test` for pure functions.

**Spec:** `docs/superpowers/specs/2026-10-17-ui-revamp-design.md` (read it with this plan). Mockups: `docs/superpowers/specs/2026-10-17-ui-revamp-mockups/` (`supervisor-sites.html` option 1, `crew-reporting.html` option A, `landing.html`).

## Global Constraints

- No backend, schema, RPC or Edge Function changes. `src/dev/mockBackend.ts` may change (mock only).
- No new runtime dependencies unless a task names one. Motion is CSS transitions/keyframes plus small hooks.
- Theme values exactly as the spec's "Theme" section: page `#ffffff`, sidebar `#f7f7f5`, fill `#f1f1ef`, hover `rgba(55,53,47,.06)`, ink `#37352f` / `#787774` / `#9b9a97`, divider `rgba(55,53,47,.09)`, accent `#2383e2`, Notion tag palette, system UI font stack, radius 4–6px controls / 10–12px cards, Notion layered shadow for floating panels.
- Hazard index bands come from `riskLevel()` in `src/lib/monitoring.ts`: ≥7 High (red), ≥4 Elevated (orange), else Low (green). Never color alone: always the number, plus label where space allows.
- Icons: gray (`#91918e`) outline, 24 grid, stroke 1.7, round caps/joins. No emoji anywhere in the UI.
- Every animation is disabled under `@media (prefers-reduced-motion: reduce)`.
- Keep these ids/accessible names where the control still exists: `#site`, `#push-title-input`, `#push-body`, `#push-blocker`, `#safety-checklist`, `#crew-roster`, `#risk-now`, buttons "Sign in", "Sign out", "Send alert", "Acknowledge", "Generate safety draft". Update tests whose navigation changed; never delete coverage.
- Landing copy is fixed by the spec (headline, sections, "Try it with 50+ real power plant sites."). No gray paragraph under the hero headline. Never "Florida".
- Laptop (≥1024px) is the design target; at <768px layouts stack and the drawer becomes a bottom sheet.
- Run before every commit: `npm run build` (typecheck + build) and the task's tests. Full suite at the end: `PLAYWRIGHT_MODE=design npx playwright test` and `npm run test:frontend`.

## Review Focus

1. **Location denied or unavailable when opening the report drawer** → pin starts at the site center, hint "Couldn't get your location. Click the map to place the pin.", Send still works. (Task 8 test.)
2. **A site with `risk_now = null`** (no score yet) → table shows "—", sorts last, map pin is gray, nothing crashes. (Task 5 test.)
3. **Lightning stop-work countdown when `last_strike_at` is older than 30 minutes or null** → no banner, no negative countdown. (Task 7 unit test.)
4. **Switching sites while the report drawer is open or a photo is attached** → drawer closes and the photo is discarded via `discardPhoto()` as today. (Task 8 test.)
5. **Deep link or refresh on `#/crew` as a crew member** (supervisor-only page) → redirect to that role's home (`#/site`), no blank page. (Task 2 test.)
